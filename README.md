### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удаленно включать и выключать отопление в своих домах.
- Система поддерживает изменение статуса отопления (включено/выключено) и отображение температуры по запросу.
- Можно узнать дату последнего изменения статуса отопления и дату добавления датчика.

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс.
- Система поддерживает добавление/удаление/обновление/получение информации о датчиках температуры.
- Пользователи могут привязывать датчики к определенным комнатам.
- Температура может задаваться в разных единицах измерения (Цельсий, Фаренгейт).

### 2. Анализ архитектуры монолитного приложения

Перечислите здесь основные особенности текущего приложения: какой язык программирования используется, какая база данных, как организовано взаимодействие между компонентами и так далее.

Основной язык: Go
База данных: PostgreSQL
Взаимодействие между компонентами: Монолитное приложение. Компоненты имеют тесную связь и взаимодействуют напрямую.
С таким подходом нельзя масштабировать отдельные части приложения для увеличения производительности или добавления новых функций без изменения всего приложения.

Используется скрипт для поднятия докер контейнера и запуска приложения. Такие скрипты сложно поддерживать и масштабировать, без ручных изменений и повторного деплоя не получится увеличить количество инстансов приложения, добавить новые сервисы и так далее.

### **4. Проблемы монолитного решения**

- Плохо масштабируется, нельзя отдельно масштабировать нагруженые части приложения
- Сложно поддерживать, изменения в одной части приложения могут повлиять на другие части
- Сложно добавлять новые функции, нужно собирать весь монолит и деплоить
- Проблема с надежностью, если одна часть приложения падает, может упасть весь монолит


Если вы считаете, что текущее решение не вызывает проблем, аргументируйте свою позицию.

# Задание 5. Работа с docker и docker-compose

Перейдите в apps.

Там находится приложение-монолит для работы с датчиками температуры. В README.md описано как запустить решение.

Вам нужно:

1) сделать простое приложение temperature-api на любом удобном для вас языке программирования, которое при запросе /temperature?location= будет отдавать рандомное значение температуры.

Locations - название комнаты, sensorId - идентификатор названия комнаты

```
	// If no location is provided, use a default based on sensor ID
	if location == "" {
		switch sensorID {
		case "1":
			location = "Living Room"
		case "2":
			location = "Bedroom"
		case "3":
			location = "Kitchen"
		default:
			location = "Unknown"
		}
	}

	// If no sensor ID is provided, generate one based on location
	if sensorID == "" {
		switch location {
		case "Living Room":
			sensorID = "1"
		case "Bedroom":
			sensorID = "2"
		case "Kitchen":
			sensorID = "3"
		default:
			sensorID = "0"
		}
	}
```

2) Приложение следует упаковать в Docker и добавить в docker-compose. Порт по умолчанию должен быть 8081

3) Кроме того для smart_home приложения требуется база данных - добавьте в docker-compose файл настройки для запуска postgres с указанием скрипта инициализации ./smart_home/init.sql

Для проверки можно использовать Postman коллекцию smarthome-api.postman_collection.json и вызвать:

- Create Sensor
- Get All Sensors

Должно при каждом вызове отображаться разное значение температуры

Ревьюер будет проверять точно так же.
